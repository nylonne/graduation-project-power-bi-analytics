# Contributing

This repository is maintained by the Graduation Project group. Contributions should preserve shared ownership, report reliability, data confidentiality, and clear attribution.

## Before editing

1. Tell the group which area you will change.
2. Confirm that nobody else is editing the PBIX file.
3. Create a backup or a clearly named working copy before structural report changes.
4. Do not commit credentials, personal data, or unapproved source extracts.

## Change and handoff process

1. Make one coherent change at a time.
2. Test affected pages, filters, totals, formatting, and navigation in Power BI Desktop.
3. Describe the change, affected pages, validation performed, and data impact in the pull request.
4. Ask at least one group member to review material changes before merging.
5. Update `README.md`, `TECHNICAL.md`, or `SETUP.md` when the workflow, architecture, or setup changes.

## Power BI file policy

`.pbix` is a binary file and cannot be meaningfully line-merged. Avoid concurrent edits. If two versions diverge, agree on one owner to reconcile changes in Power BI Desktop; do not attempt an automated merge.

## Credit and conduct

Keep the contributor list in `README.md` accurate. Every group member whose work is used in the dashboard, data model, documentation, testing, or presentation must receive appropriate credit.
